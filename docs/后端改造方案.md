# 新传研背 · 后端改造方案（V6.0 云端化）

> 编写：小code ｜ 日期：2026-09-24 ｜ 状态：**待评审**
> 目标：把数据从"各浏览器各自的本地存储"升级为"服务器中央数据库"，实现多用户共享与云端上线。

---

## 一、为什么要做后端（现状痛点）

| 现状 | 问题 |
|---|---|
| 题库/收藏/笔记/进度都存在浏览器 `localStorage` | 换台设备/换个浏览器，数据全没了 |
| 后台发布的内容写在管理员自己的浏览器里 | 学生看不到管理员发的题 |
| 后台账号密码写死在前端代码 | 懂技术的人按 F12 就能看到，不安全 |
| 无用户体系 | 无法区分谁是谁，无法做数据分析 |

**一句话**：现在是"每人发一本自己的笔记本"，要变成"有一个公共图书馆"。

---

## 二、架构对比

### 现状（纯前端）
```
浏览器/Electron
  ├── 前端页面 (HTML/JS)
  ├── localStorage / Electron 共享文件  ← 所有数据在这
  └── start-server.js（只做静态文件 + AI 代理）
```

### 目标（前后端分离）
```
浏览器/Electron
      │  HTTP (REST API)
      ▼
  后端服务 (Node.js + Express)   ← 新增 apps/server/
      │
      ▼
  数据库 (SQLite，单文件)         ← 集中存所有数据
```
> 部署：Nginx 反向代理 + HTTPS 挂在后端服务前面，公网访问。

---

## 三、技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 后端框架 | Node.js + Express | 与现有项目同一技术栈，无需学新语言 |
| 数据库 | **SQLite**（起步） | 零配置、单文件、免费；单机云服务器足够 |
| 数据库升级项 | MySQL / PostgreSQL | 用户量大时可平滑迁移 |
| 身份认证 | JWT（Token） | 前后端分离标准方案 |
| 密码存储 | bcrypt 加密 | 不存明文密码 |
| 文件解析/上传 | multer + 已有 pdf.js/mammoth | 复用现有前端解析能力 |
| 部署 | Nginx + PM2 + HTTPS | 标准、稳定 |

## 四、数据库设计（主要表）

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `users` | 用户账号 | id, username, password_hash, nickname, phone, role(admin/student), created_at |
| `questions` | 题库（名词/简答/论述/实务） | id, question_type, title, category, tag, status(draft/published/unpublished), content_json, created_at |
| `materials` | 学习资料 | id, title, source_type, file_type, word_count, chapter_info, parse_status, uploaded_by |
| `favorites` | 收藏关系 | id, user_id, question_id, created_at |
| `notes` | 笔记 | id, user_id, question_id, content, created_at |
| `study_progress` | 学习进度 | id, user_id, question_id, rating(认识/模糊/不会), updated_at |
| `exam_history` | 考试/训练历史 | id, user_id, type, question_index, answer, updated_at |
| `feedback` | 用户反馈 | id, user_id, content, created_at |
| `publish_logs` | 发布日志 | id, question_id, action, operator, created_at |

> 设计原则：一题多用户收藏/笔记/进度用"关系表"；题库与学生数据分离。

## 五、API 接口清单（REST）

### 认证 `/api/auth`
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录（返回 JWT） |
| GET | `/api/auth/me` | 获取当前用户 |

### 题库 `/api/questions`
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/questions?type=&category=&status=` | 列表（学生端只看 published） |
| GET | `/api/questions/:id` | 详情 |
| POST | `/api/questions` | 新增（管理员） |
| PUT | `/api/questions/:id` | 编辑（管理员） |
| DELETE | `/api/questions/:id` | 删除（管理员） |
| PATCH | `/api/questions/:id/status` | 上架/下架 |

### 资料 / 收藏 / 笔记 / 进度 / 考试 / 反馈
| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST/DELETE | `/api/materials` | 资料管理 |
| GET/POST/DELETE | `/api/favorites` | 我的收藏 |
| GET/POST/PUT/DELETE | `/api/notes` | 我的笔记 |
| GET/PUT | `/api/progress` | 学习进度 |
| GET/POST | `/api/exam-history` | 训练历史 |
| GET/POST | `/api/feedback` | 反馈 |
| GET | `/api/admin/stats` | 后台数据概览 |

> 所有接口统一返回 `{ code, message, data }`；鉴权接口带 `Authorization: Bearer <token>`。

## 六、前端改造点

| 文件 | 改动 |
|---|---|
| `apps/mobile/app/xc-sync.js` | 数据同步层：`localStorage` → `fetch` 调 API（保留本地缓存兜底） |
| `apps/admin/src/data.js` | 后台"前端数据库" → 改为调 API |
| `apps/mobile/app/login.html` | 登录改为调 `/api/auth/login` |
| 各详情/列表页 | 数据加载改为 `fetch` API |
| `start-server.js` | 保留静态服务；AI 代理不动 |

**兼容策略**：前端仍保留 localStorage 作为"离线缓存"，网络失败时降级本地，保证可用性。

## 七、分阶段实施计划

| 阶段 | 内容 | 预估工时 | 交付物 |
|---|---|---|---|
| **阶段 1** | 后端骨架 + 数据库建表 + 健康检查 | 0.5–1 天 | 可启动的 `apps/server` |
| **阶段 2** | 题库 API + 后台管理接入 | 1–2 天 | 后台发题真正入库 |

| **阶段 4** | 用户账号体系（注册登录/JWT/权限） | 1 天 | 真·登录 |
| **阶段 5** | 部署配置 + 数据迁移脚本 | 0.5–1 天 | 可上云 |
| **合计** | | **约 4–6 个工作日** | |

> 每阶段完成即回归测试（沿用现有 Playwright 用例）+ 提交 GitHub，可单独回退。

## 八、风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 现有 localStorage 数据迁移丢失 | 中 | 写一次性迁移脚本；迁移前备份 |
| 后端引入后前端页面回归 | 中 | 保留本地兜底；每阶段跑回归 |
| 安全性（密码/接口） | 高 | bcrypt 加密 + JWT + 接口鉴权 + HTTPS |
| 单机 SQLite 并发瓶颈 | 低 | 用户量上来再迁 MySQL，接口层不变 |
| 工作量超出预期 | 中 | 分阶段交付，优先阶段 1–2 出可用成果 |

## 九、部署方案（上云）

1. 云服务器（Linux，1核2G 起步即可）
2. 安装 Node.js + PM2（进程守护）
3. Nginx 反向代理 + 域名 + HTTPS（Let's Encrypt 免费证书）
4. SQLite 数据文件定期备份（脚本 + 定时任务）
5. 环境变量管理密钥（不写进代码，沿用现在的做法）

> 成本参考：一台基础云服务器约 ¥60–100/年（学生机/活动机更便宜）。

## 十、给老板的"人话总结"

- **要干嘛**：加一个"中央仓库"（后端+数据库），让后台发的题所有人都能看到、大家的数据存到服务器不会丢。
- **要多久**：我干活大约 **4–6 个工作日**，分 5 步，每步都能验证、能回退。
- **要花钱吗**：开发**不花钱**（全免费开源）；上线时才需要一台云服务器（约几十块到一百块一年）。
- **风险大吗**：不大，分步做、每步测试、随时能退。
- **建议**：先做**阶段 1–2**（后端骨架 + 题库入库），跑通了再继续，稳妥。
